Committed first in 092c392 (docs/is84-prediction.txt). Convention and
comparison committed in 2b81f3e before the test or implementation edits.
Trailing operands, exact source spelling, empty/Unicode/raw arguments,
-- before a hyphen filename, option-looking program words and executable
shebangs were predicted red first. Conform-run's absent argv and protocol
options were predicted unchanged. The argv parser uses one trailing
variadic positional starting at FILE, not a second positional that would
let lupin consume a script's flags. No lossy string conversion occurs.

5. Rulings and remaining work

R-is84-1 — argv[0]. Recommend the entry filename as given, not a
canonicalized path or the compiler's generated executable name. Implemented
for both human front doors. The differential prints wolf's actual
invocation name alongside lupin's; it compares identical trailing argv
on the same source without pretending command conventions are identical.
Cost: no runtime/stdlib change.

R-is84-2 — stdin argv. Recommend no new stdin framing mode. Source stdin
already works as lupin - ARGS; building that small, unambiguous case is
included. A second input framing protocol would compete with program
stdin and needs explicit framing, limits and error rules (medium cost).

R-is84-3 — -e CODE ARGS. Recommend deferring program execution snippets.
-e already evaluates a REPL expression and prints its typed result; silently
turning it into Python -c would break users. A separate execution spelling
needs a source-name/argv[0] convention and documentation (small-to-medium
cost). Existing -e remains unchanged.

R-is84-4 — directory/package entry. Recommend a separate package-entry
feature, not implicit file/directory guessing in this pass. It needs entry
metadata, root discovery, diagnostics and independent package tests
(medium cost). No directory behavior was added.

R-is84-5 — script-flag completion. Recommend a future declarative script
metadata protocol; never execute arbitrary scripts to discover flags.
Shell adapters, escaping and a trust boundary make this medium-to-large
cost. No implicit completion hook was added.

R-is84-6 — std.args draft. Recommend a pure wolf-std parser taking a
List[str], with an optional env_args wrapper, not a new interpreter
builtin. Draft surface: an option schema declaring long names, arity,
repeatability and optional short names; parse(schema, words) returns
values plus remaining positionals or an indexed structured error.
-- terminates flags; --name=value binds one value; unknown flags and
missing values are explicit errors. Preserve empty values and repetition;
never guess short-option bundling or decode raw bytes lossily. A separate
byte-oriented API can be designed if needed. Implementation, semantic
choices and std tests belong to the stdlib track (medium cost); draft only.
