## 4. Evidence index

### The cause, confirmed

`d45084b` alone. It replaced std's `CommandExt::exec` with nix's safe
`execve`. Rust's runtime sets SIGPIPE to ignored before `main`. POSIX
`execve` keeps an ignored signal ignored and resets only caught ones, so
every image 0.1.57 exec'd started with SIGPIPE ignored. std's exec
(0.1.56) set it back to the default first. `e603e6d` touches only the
spawn paths. Measured black-box with the published archives in hasu's
container, the new image being `cat /proc/self/status`
(`ci/r41e/calib-published.log`, programs in `ci/r41e/calib/`):

| lupin | start | image SigIgn | image SigBlk |
|---|---|---|---|
| 0.1.56 | plain | `0x0` | `0x0` |
| 0.1.57 | plain | `0x1000` | `0x0` |
| 0.1.56 | SIGPIPE+SIGUSR1 blocked | `0x0` | `0x1200` |
| 0.1.57 | SIGPIPE+SIGUSR1 blocked | `0x1000` | `0x1200` |
| candidate | plain / blocked | `0x0` / `0x0` | `0x0` / `0x1200` |

The issue's premise about the mask does not hold at Rust 1.97.1. No path
empties an inherited mask, 0.1.56's std exec included. The mask was never
part of the regression.

### Every program-starting path, before and after

| path | mechanism | SIGPIPE in the new program, 0.1.57 -> 0.1.58 | inherited mask |
|---|---|---|---|
| `os_exec` | nix `execve` (`exec_replace`) | **ignored -> default** | passed through (both) |
| `os_spawn`, `os_spawn_with` | std `Command::spawn` (`spawn_in`) | default -> default | passed through |
| `os_spawn_fds`, the pipelines built from it and `os_pipe` | std `Command` (`spawn_job`, no group) | default -> default | passed through |

| `os_fork` | refused by name | starts nothing | n/a |
| lupin's group cleanup after a refusal (`end_group`'s `sh -c kill`) | std `Command::status` | default (the same std path; not witnessed alone) | passed through |
| `lupin diff`'s counterparty (`differ::invoke_tier`) | std `Command::spawn` | default (the same std path; not witnessed alone) | passed through |

Witnessed for the first five rows by `tests/exec_sigpipe_r41e.rs` on both
hosts and by the calibration (`ci/r41e/calib-published.log`,
`ci/r41e/calib-candidate-e194b69.log`).

### R-r41e-1 (recommended A, implemented)

**(A) a safe API before the direct `execve`**: signal-hook's
`flag::register(SIGPIPE, flag)`. It is a safe function: the crate's own
`unsafe_code = "forbid"` build compiles it. It makes SIGPIPE caught by a
handler that only stores to an `AtomicBool`, and POSIX `execve` resets
every caught signal to its default in the new image. nix cannot do this
safely: its `signal` and `sigaction` are `unsafe fn`. Its safe
`pthread_sigmask` and `posix_spawn` change no disposition in the calling
process. If the exec fails, `low_level::unregister` removes the action.
Measured on Linux, lupin's SIGPIPE is then ignored again exactly as
before (SigIgn `0x1000`, SigCgt without bit 12; `ci/r41e/calib-candidate-e194b69.log`),
and `a_failed_exec_puts_lupin_sigpipe_back` pins it.

**Audit.** `signal-hook = "=0.3.18"` with default features off. It is
MIT/Apache-2.0, published 2025-05-09, the long-stable 0.3 line (139 M
downloads), not yanked, checksum `d881a16c…6e2`. It pulls in
`signal-hook-registry` 1.4.8 (MIT OR Apache-2.0, checksum `c4db69cb…b1b`).
That crate's own dependencies, `libc` and `errno` 0.3.14, were already in
the lock. Exactly two packages were added to `Cargo.lock` and none moved
(`beb976b`). Both checksums equal crates.io's. The sources were not read
(RULES §1): the audit rests on the published documentation, crates.io
metadata and the black-box tests.

**(B) rejected.** Going back to std's exec behind `e603e6d`'s header
guard reopens R-is81-1's shell fallback. Measured: 0.1.56's `os_exec` of
a `#!` script whose interpreter has no header ran the script's text under
`/bin/sh` (`SCRIPT-TEXT-RAN-UNDER-SH`, exit 71). The kernel answers
ENOEXEC, and glibc's exec retries under the shell. The guard admits `#!`,
so it cannot stop that. It is also a check-then-exec race against a file
replaced between the read and the exec. **(C)** was not needed.

### R-r41e-2 (new; recommended A, implemented)

The mask across `os_exec`. **(A)** pass the inherited mask through
unchanged, as 0.1.56, every spawn path and a native image do. **(B)**
unblock SIGPIPE at exec only. A means no mask code at all. B would make
exec differ from every spawn and from the native machines.
`exec_passes_an_inherited_mask_through` and
`every_spawn_path_passes_an_inherited_mask_through` pin A.
