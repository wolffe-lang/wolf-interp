### #310 — s270b's copies (`13216e8`)

Two changes in the evaluator's store path, both from `[mem.region.edge.elem]`
and `[mem.region.outer-write]`:

1. **A plain store's copy is the ambient's.** A plain `push`, index store
   or `Map` store of a value holding a `List` or `Map` copies it where the
   store runs: every container the value reaches is a fresh buffer charged
   to the current region; a `str` keeps sharing (ruling #35). Only a value
   with a container homed elsewhere is rebuilt, and a list of scalars is
   never walked. `region_outer_write_push_plain_copy.lu`: exit(0) `1 100
   99 2000` → `trap(region-fault)`, E1010's dynamic counterpart. Its index
   twin (`stores/index_store`, wolf `fail(E1004)`): exit(0) →
   `trap(region-fault)`, E1004's counterpart. A struct of a `str` and an
   `int` pushed plainly still prints `1 outer 1`.
2. **`copy e` at a container store through a `mut` parameter is the
   container's.** The callee has no lexical block, and the clause's clean
   stores ("container stores of scalars or of `copy`s (the container's
   own region)") hold wherever they sit. `region_outer_write_push_copy_call.lu`:
   `trap(region-fault)` → exit(0) `4 100000 101 64 4 0 2000`. A flat field
   store of a `copy` keeps R-is81-3's reading: is81's five
   `region_kept_arg_*` rows still trap with `28`.

Nothing else moved: s270b's other five rows and #940's two answer as at
the base.

### #304 — the first frontend diagnostic (`4219775`, `65166fa`, `1c0ebf3`)

**E0202.** 45 shapes measured on wolf 0.2.36 (`tests/fixtures/is82/delims/`,
`DELIMS` in the witness): 25 parted at the base (codes on 12, spans on 13),
all 45 agree at the head, code and span. The rule, read from
`[proto.record.first]` ("a boundary diagnostic sits at its opener") and the
registry's E0202 ("the parser instead stops at the next declaration
keyword and reports the wreck once"), as lupin now applies it:

- an interpolation is a group of its own: a closer inside `{…}` of a
  string never closes an opener outside it (`print("{\"name\": \"x\"}")`,
  the issue's JSON shape: E0102 → E0202 at the `(`);
- a wreck (a closer of another kind, a statement keyword `let var const
  struct enum trait impl use import` inside a `(`/`[`, the end of an
  interpolation or of the file) is reported at its INNERMOST opener;
- a parse error inside a `(`/`[` group whose own closer comes before any
  wreck is just the parse error (`foo(1 2)` stays E0201); one whose group
  never closes reports the group's opener (`(1` then `foo([2` is E0202 at
  the `(`).

The parser's unit test pinned `fn f(p: proc` at EOF as E0206; wolf
answers E0202 at the `(` (`[4,5]`), and the test now says so (`1c0ebf3`).

**E0406.** lupin had never emitted E0406, so the issue's "wolf E0412,
lupin E0406" cannot be 0.1.56's answer as written; the pair reproduces the
other way round. A call whose callee is a local the resolve walk classes

### #295 — s261's argv (`481c656`, `6dac011`, `d76e0a9`, `ec3e024`)

- `conform-run --argv-hex=HEX` (and `run`), repeated, argv[0] first: an
  even number of hex digits, either case; empty is an empty argument; a
  NUL byte or a malformed digit is a tool error naming `--argv-hex` (exit
  2, no record). Without it argv is absent, the checked machine's default.
- `env_args()` is argv[1..] as text and never decodes argv[0];
  `env_arg0()` decodes argv[0] alone, empty when argv is absent, a
  `[mem.region.escape]` site (`argv/name_escape`: wolf E1010, lupin
  `trap(region-fault)`); `env_args_bytes()` is every argument as bytes.
  A text reader meeting a non-UTF-8 argument traps `argument-utf8` with
  the compilers' words in `trap_message` (`argument 2 is not UTF-8; read
  it with env_args_bytes()`). Every answer equals the checked machine's
  (`argv_hex_*` witnesses).
- `corpus/os/arg0.lu` and `os/args_bytes.lu`: unsupported → exit(0),
  into the run ledger.
- **R-is82-3 (recommended A, implemented):** (A) the trap vocabulary is the
  pin's fourteen, `stack-overflow` included (lupin never raises it; it
  must read it in another machine's records and the bundle ships the set);
  (B) add only `argument-utf8`. A: the bundle's `vocab/traps.json` says
  "closed", and a closed set that omits a member is wrong for every
  consumer. `6dac011` alone does not compile (the rule registry's array
  length); `d76e0a9` is its fix, one commit later.
